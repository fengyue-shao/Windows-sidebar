# 0.8.1.0-preview：顶部下拉 UI

2026-10-01。本地开发预览，不是正式 MSIX 发布，不推送远程、不覆盖已安装版。

## 使用

构建产物位于工作区 `build-plugin-integration/Release/appqt_rainmeter.exe`，Qt DLL 和插件随该目录部署；不要只复制 EXE。

正常启动默认隐藏；在所选显示器顶部中央触发区停留约 240 ms，或按全局 `Ctrl+Alt+Space`，只显示精简顶部栏。双击顶部中间区域展开/收起卡片；右侧按钮进入设置，不再显示展开/隐藏按钮。全局快捷键可手动完全隐藏；窗口内 Escape 从卡片回到精简栏，再次按下完全隐藏（弹层打开时先处理弹层）。`--preview-cards` 参数立即展示预览并暂停自动隐藏，便于审阅；不修改用户设置。

精简栏离开后约 4 秒隐藏；卡片遵循自动隐藏开关（启用时离开约 1.2 秒）。停留触发边缘也计入交互区域。打开日历/设置、聚焦编辑框或按住鼠标时暂停自动隐藏。手动隐藏后边缘触发必须先离开触发区重新进入。精简栏不接受键盘焦点，避免悬停唤出抢走用户正在输入的焦点；手动展开卡片后才激活窗口。

## 实现

- `Main.qml` 独立三态壳层，不再用旧的 `uiSettings.expanded` 布尔值控制窗口；旧值保留供兼容，不恢复旧版展开状态。
- `DropdownController` 通过 RegisterHotKey / WM_HOTKEY 提供真正的全局唤出，并用 Qt 全局逻辑坐标轮询所选屏幕边缘。
- 窗口依据屏幕 availableGeometry 顶部居中；监控采用透明双列约束容器，620 逻辑像素以下回退单列。
- `QWindow::setMask` 将窗口输入与可见卡片区域对齐，保留圆角、滚动裁剪和透明间隙。设置/日历打开时临时扩大至窗口边界以处理点击外部关闭，关闭后恢复；这时窗口内透明空隙不会穿透。
- 内置通知、专注、剪贴板、工具箱及动态插件页面继续复用；工具箱仍是唯一插件管理 GUI。
- 首版系统控制继续复用现有声音/网络/蓝牙综合控制卡，展开细节仍在卡片内；并非将 Figma 示例的每个功能卡一比一拆开。
- 独立卡片使用新增的不透明 cardSurface 主题角色。整体透明度下限迁移到 94%，防止移除旧全背景后文字与桌面混叠。
- 修复 QML 引擎晚于上下文服务销毁造成的退出阶段空对象绑定错误；自定义顶部按钮使用 Basic 控件，避免 Windows 原生样式不支持自定义的问题。

## 验证

Release 构建、Qt 依赖部署通过。运行以下脚本可复测三态、窗口尺寸、顶部栏/卡片间隙命中区域、内置页面与当前启用插件加载；不会调节系统音量、无线或执行终端命令：

```powershell
powershell.exe -NoProfile -File scripts/test-dropdown-ui.ps1 -Executable ../build-plugin-integration/Release/appqt_rainmeter.exe
```

最新冒烟输出包含 `UI_SELF_TEST PASS Hidden/Bar/Cards + geometry + input regions + pages`，退出码 0，无 QML 类型/绑定/组件加载错误。

实际桌面截图检查了顶部栏、监控双列、工具箱和设置位置；窗口检查确认监控卡片中间透明间隙命中下方窗口而不是预览应用。测试环境为单显示器 1920 × 1080、125% 缩放。截图保留在仓库外工作区 `work/screen-captures`，不提交私人桌面内容。

历史首版实际输入验证通过展开/收起/隐藏按钮与边缘、全局快捷键；当前精简版已实际验证顶部中间双击收起、从精简栏打开设置。回归脚本检查三态与设置展开高度。透明卡片间隙仍使用独立输入区域，不铺设整页输入底板。

构建与测试在允许访问本机 SDK/桌面会话的环境中运行；受限沙箱直接启动曾返回 0xC0000409、屏幕捕获曾返回无效句柄，放行相同范围的检查后通过，不能把沙箱失败当作真实桌面应用验证结果。

## 已知边界

- 直接 EXE 没有 MSIX 包身份，通知监听提示系统元素不可用；不表示顶部 UI 崩溃。本次未验证包身份通知授权、真实 Wi-Fi/蓝牙连接或终端命令回归。
- 尚未在多显示器、负坐标、不同 DPI、顶部任务栏、独占全屏环境中实测；目前没有全屏应用边缘唤出抑制。
- 页面切换/展开采用即时窗口尺寸变化；后续可增加有命中区域同步保障的动画。
- 当前全局键固定 Ctrl+Alt+Space；冲突反馈已有，用户自定义快捷键留待后续。
- Figma Starter MCP 额度耗尽，设计上下文读取仍失败；本版依据此前已审核并保存的设计和现有组件制作，不宣称逐像素对齐。
- 动态插件仍使用兼容的完整内容卡与 18 px 内边距；大量插件导航溢出需后续菜单化处理。

## 第二轮：细粒度卡片

通知、专注、剪贴板和工具箱移除整页底板，只保留透明约束容器。

- 专注分为页标题、计时、操作、跨页面提示、三个节奏和完成统计八张独立卡片。`FocusClockCard` / `FocusPresetCard` 只接收状态和发送选择信号；页面连接同一个 C++ `FocusTimer`，切换页面不重建计时。完成次数清零有独立按钮。
- 通知分为媒体/媒体空状态、通知工具栏、空状态和逐条通知卡片；列表无大背景和可见滚动条。通知菜单打开时扩大命中区域并暂停自动隐藏，关闭或收起时恢复。
- 剪贴板标题与状态是一张管理卡片，每条历史与空状态独立显示，保留原有置顶、删除和预览功能。
- 工具箱分为管理、加载状态、逐插件和安全说明卡片，仍是插件管理唯一 GUI。
- `CardSurface.qml` 统一独立表面；`CardRegions.js` 接收显式表面列表，并按滚动视口裁剪原生命中区域。空白区域不生成输入底板，不收集隐藏或越界卡片。视觉组件不持有新的业务状态。

Release 构建及冒烟测试通过，新增专注卡片数量与双列间隙断言。通过本地 screen-capture-read 技能观察专注、通知空状态、剪贴板空状态与工具箱；专注双列间隙的原生窗口查询命中下方 Codex 窗口。没有修改专注计时、剪贴板条目、插件启停或系统控制；真实通知、非空剪贴板、长列表滚动及通知菜单交互仍需包身份/数据条件下回归。截图只保存在仓库外工作区，不提交。

官方接口参考：[RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)、[QWindow::setMask](https://doc.qt.io/qt-6/qwindow.html#setMask)。
